# Intellora Tech — website

A twenty-page site built as short, focused pages rather than long scrolling ones. Plain HTML, CSS and JavaScript at deploy time: no framework, no bundler, no runtime dependency.

## Structure

```
/                                   Home
/capabilities/                      Hub — six pillars
/capabilities/analytics-bi/         ┐
/capabilities/data-governance/      │
/capabilities/security/             │ one short page per pillar
/capabilities/ai-machine-learning/  │
/capabilities/database-engineering/ │
/capabilities/aws-cloud/            ┘
/industries/                        Sector experience, three tiers
/tools/estimator/                   Programme estimator (3-step wizard)
/tools/maturity/                    Data maturity check
/blog/                              Insights index
/blog/<slug>/                       Articles
/about/                             The practice and credentials
/contact/                           Scoping call and how to reach us
/payment/                           Stripe Checkout — see PAYMENTS.md
/payment/success/  /payment/cancel/ Checkout return pages

assets/site.css     Design system — tokens, layout, components
assets/site.js      Theme, nav, estimator, maturity check, payment
assets/theme.js     Applies the saved theme before first paint
functions/          Cloudflare Pages Functions (Stripe)
build.py            Generates every page from one shared layout
```

## Editing content

Every page is generated by `build.py` so the header, footer, metadata and design stay identical across all twenty. Edit the content there, then:

```bash
python3 build.py
```

That rewrites the HTML files, `sitemap.xml` and `robots.txt`. Commit the generated files — the host serves them directly, with no build step of its own.

**Adding a blog post:** add an entry to `POSTS` at the top of `build.py` (slug, title, date, category, reading time, excerpt), then a matching `post_page(POSTS[n], """...""")` call with the article body in HTML. It appears on `/blog/`, in the sitemap, and in the "more field notes" links on other posts automatically.

**Adding a capability:** add a tuple to `PILLARS` and a `pillar_page(...)` call. The hub grid and both footers pick it up.

## Design system

- **Type.** Plus Jakarta Sans for headings and UI, Source Serif 4 for body copy at 17–18px with 1.75 line-height, JetBrains Mono for labels. Prose is capped at 68 characters per line.
- **Colour.** Each area of the site sets `data-accent` on `<body>` — emerald for capabilities and company pages, indigo for industries, gold for tools, coral for insights, plum for AI. The accent drives buttons, links, chips and the soft colour fields painted behind every page.
- **Dark mode.** Follows the system setting; the header toggle overrides it and persists to `localStorage`.
- **Motion.** Reveal-on-scroll and hover lifts, all disabled under `prefers-reduced-motion`.

## Accessibility and progressive enhancement

Every page is readable and navigable with JavaScript disabled — the estimator and maturity check show `<noscript>` fallbacks that point at email. Skip link, one `h1` per page, visible focus rings, `aria-current` on the active nav item, and labelled form controls throughout.

## Deploying

Cloudflare Pages, connected to this repository. No build command, output directory `/`. The `functions/` folder is picked up automatically and needs `STRIPE_SECRET_KEY` set in the project's environment variables — see `PAYMENTS.md`.

`_headers` sets the security headers (CSP, HSTS, `X-Frame-Options`, `Referrer-Policy`). If you add a third-party script or embed, it must be allowed there or the browser will silently block it.
